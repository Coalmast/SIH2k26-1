## 0.A Component Library Strategy

> [!IMPORTANT]
> **Golden Rule:** Never write a custom component if one exists in these registries. Check in priority order:
> 1. **shadcn/ui** — `npx shadcn@latest add <name>` — already configured
> 2. **21st.dev** — `npx shadcn@latest add "https://21st.dev/r/<name>"` — animated UI blocks
> 3. **Magic UI** — `npx shadcn@latest add "https://magicui.design/r/<name>.json"` — animated effects
> 4. **Animata** — copy-paste from `animata.design/components` — 155+ micro-animations (MIT)
> 5. **Aceternity UI** — copy-paste from `aceternity.com/components` — Framer Motion cards/effects
> 6. **Rare UI** — CLI install from `rare-ui.vercel.app` — motion-rich premium components
> 7. **Inspira UI** — copy-paste from `inspira-ui.com` — Vue-inspired React animated components
> 8. **Smooth UI** — `smooth-ui.dev` components — silky transition components
> 9. **PDF CN** — shadcn-based PDF viewer components (`pdfcn.cn` registry)
> 10. **Custom build** — absolute last resort only

### i18n Automation Strategy
1. **Commit all code first**
2. Run `npx i18next-cli instrument --dry-run` — preview changes
3. Run `npx i18next-cli instrument` — auto-inject `useTranslation` + wrap JSX text in `t()`
4. Run `git diff` and manually review edge cases (template literals, non-UI strings)
5. All **new screens** written with `useTranslation` from day one — no retrofitting needed

### Admin Tables Strategy
- Use existing `components/data-table/` (TanStack Table + shadcn/ui) already in codebase
- Wire Supabase PostgREST queries via TanStack Query for server-side pagination/filtering
- No Refine or MUI DataGrid — keeps design consistent with rest of app
